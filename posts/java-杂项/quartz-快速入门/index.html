简介#

Quartz is a richly featured, open source job scheduling library that can be integrated within virtually any Java application - from the smallest stand-alone application to the largest e-commerce system. Quartz can be used to create simple or complex schedules for executing tens, hundreds, or even tens-of-thousands of jobs; jobs whose tasks are defined as standard Java components that may execute virtually anything you may program them to do. The Quartz Scheduler includes many enterprise-class features, such as support for JTA transactions and clustering.

Quartz is freely usable, licensed under the Apache 2.0 license

Quartz 是一个功能丰富的开源作业调度库，可以集成到几乎所有的 Java 应用中—从最小的独立应用到最大的电子商务系统。Quartz可用于创建简单或复杂的时间表，以执行几十、几百、甚至几万个作业；这些作业的任务被定义为标准的Java组件，几乎可以执行任何你可以编程让它们做的事情。Quartz Scheduler 包括许多企业级的功能，如对JTA事务和集群的支持。

Quartz 是免费使用的，在 Apache 2.0 许可下授权。

Tips: 光单个服务实例定时执行任务的话，Spring Scheduler 就可以完成，当然 Quartz 也有单节点模式，不过我们一般是需要它的集群模式，用上负载均衡、故障迁移等特性

重要概念#

  • Job： 需要重复执行的逻辑代码类，和 Runnable 实例很类似
  • JobDetail： 包含了 Job 对象的容器，需要唯一标识(由 name 和 group 共同组成，同 group 下不允许出现同 name)，并且可以在任务执行前将 JobData 存入 JobExecutionContext，以便 Job 执行时能从上下文中获得一些额外信息
  • Trigger： 定时任务的触发器，需要唯一标识(由 name 和 group 共同组成，同 group 下不允许出现同 name)，和 JobDetail 是多对一关系，一个 Trigger 只能有一个 JobDetail，但是一个 JobDetail 可以有多个 Trigger。
  • Scheduler： 通常一个服务实例对应一个 Scheduler 即可，它可记录若干对 JobDetail - Trigger 的关联关系，并通过线程池在必要的时候激活任务的执行。Scheduler 名称相同的实例会共同分担该 Scheduler 名下已指定的任务，即产生负载均衡、故障迁移等效果。

Tips: 官方好像没对这些定义详细描述，上面纯属我个人理解不保真。Trigger、JobDetail 的唯一标识互不相干，group1 的 Trigger 和 group2 的 JobDetail 绑定关系不成问题，没有约束。在数据库表中 name、group 是不同字段，估摸着这么设计唯一标识是有助于提升查询效率和缩小表加锁范围

MisFire 机制#

MisFire 是指到了预定时间，但对应的任务因某种原因未能准点执行业务逻辑，通常我们需要配置 MisFire 的处理机制，例如 CronScheduleBuilder 实例的 withMisfireHandlingInstructionDoNothing() 方法。 quartz 框架层最顶层只定义了两种类型

  • MISFIRE_INSTRUCTION_SMART_POLICY：智能，让下层 ScheduleBuilder 实例组件自行设计，行为各有不同
  • MISFIRE_INSTRUCTION_IGNORE_MISFIRE_POLICY：忽略 MisFire 事件

此处用 CronTrigger 的三种处理机制来抛砖引玉，其余的请自行查看源码。

类型对应函数名备注
MISFIRE_INSTRUCTION_FIRE_ONCE_NOW (默认值)withMisfireHandlingInstructionFireAndProceed()指令继续执行，检测到 MisFire 会立即执行任务，可能导致任务并发多次执行
MISFIRE_INSTRUCTION_IGNORE_MISFIRE_POLICYwithMisfireHandlingInstructionIgnoreMisfires()指令会伺机根据已 MisFire 次数而多次触发当前任务(优先保障其他任务按时触发)，可能导致任务并发多次执行
MISFIRE_INSTRUCTION_DO_NOTHINGwithMisfireHandlingInstructionDoNothing()不进行任务执行次数补偿

分布式并发问题#

有时候任务被多次触发会有副作用，某些任务我们希望能在多实例集群中满足“同一时刻只有一个实例非并发的方式执行”，那么可能需要进行如下操作

  • 为 Job 类标记 @DisallowConcurrentExecution 注解。能确保单个服务实例中，同一时刻以 JobDetail 唯一标识区分的粒度只有一个任务能被执行
  • 开启触发器分布式锁，例如 spring.quartz.properties.org.quartz.jobStore.acquireTriggersWithinLock=true。同一任务，同一时刻只有一个服务实例获得任务触发权限。
  • 关闭 MisFire 次数补偿，例如 CronScheduleBuilder cronScheduleBuilder = CronScheduleBuilder.cronSchedule(cronExpression) .withMisfireHandlingInstructionDoNothing();。
  • 扩大待检测分布式并发 Trigger 的范围，例如 spring.quartz.properties.org.quartz.jobStore.misfireThreshold=500(毫秒)，MisFire 阈值小范围就大，但是过小又容易引发过于敏感导致 MisFire 误判定而没有执行任务。细节有兴趣可以查看 org.quartz.impl.jdbcjobstore.JobStoreSupport#acquireNextTriggers 处源码。

QuartzJobBean 与 Job 区别#

QuartzJobBean 是 Job 的升级版，Spring 官方示例是用的 QuartzJobBean，尽管我并不觉得这个特性会有多大作用。

他们都能使用 @Autowired 相关注解，但 QuartzJobBean 还能额外用属性的 set 方法从 JobDetail 的 JobDataMap 中按 key 找到值自动注入到 QuartzJobBean 的属性中。
