简介#

With tens of thousands of users, RabbitMQ is one of the most popular open source message Brokers.From T-Mobile to Runtastic, RabbitMQ is used worldwide at small startups and large enterprises.

RabbitMQ is lightweight and easy to deploy on premises and in the cloud. It supports multiple messaging protocols. RabbitMQ can be deployed in distributed and federated configurations to meet high-scale, high-availability requirements.

RabbitMQ runs on many operating systems and cloud environments, and provides a wide range of developer tools for most popular languages.——引自官方文档

RabbitMQ 拥有数以万计的用户，是最受欢迎的开源消息代理之一。从 T-Mobile(国外一家公司) 到 Runtastic(阿迪达斯名下的运动软件)，RabbitMQ 在全球范围内被用于小型创业公司和大型企业。

RabbitMQ 是轻量级的，并且易于在场所和云中部署。它支持多种消息传递协议。RabbitMQ 可分布式部署和 federated configurations(博主也不理解这个概念)，并满足高规模、高可用性要求。

RabbitMQ 可在许多操作系统和云环境中运行，并为大多数流行语言提供广泛的开发人员工具。

重要概念#

  • Broker： 即消息队列的服务端，生产者、消费者都需要接入到 Broker。消息的流转路径示例 生产者→Broker→ Exchange → Queue → 消费者
  • Producer： 生产者，创建消息并尝试投递到 Broker
  • Consumer： 消费者，尝试从 Broker 接收由生产者投递的消息
  • Queue： Broker 中消息的实际容器，通过绑定与 Exchange 建立关系，并由该绑定关系决定消息路由具体规则
  • Exchange： 消息交换机，按特定规则将自身收到的消息分发到对应的 Queue中，Exchange 有 5 种类型
    • Default Exchange： 这是一种默认行为，每个 Queue 默认会以自身 Queue 名称为 routing key 绑定到该 Exchange 之上
    • Direct Exchange： Queue 在绑定该 Exchange 时，需提供 routing key，消息只会流转到与自身 routing key 完全一致的 Queue 中
    • Fanout Exchange： Queue 在绑定该 Exchange 时，无需 routing key，无差别的把消息路由到任何与该 Exchange 有绑定关系的 Queue
    • Topic Exchange： 可以理解为 Direct Exchange 2.0，允许 routing key 存在通配符，A* —— 匹配 A 开头的任意两个字符； A# —— 匹配 A 开头的任意数量字符
    • Headers Exchange： Queue 在绑定该 Exchange 时，无需 routing key，可追加单个或多个消息 Headers 里的键值要求，有 “至少满足任意一条键值要求” 和 “必须满足全部键值要求” 两种匹配模式，匹配成功该 Exchange 才会将消息流转到对应的 Queue
