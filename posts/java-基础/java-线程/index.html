什么是线程#

线程（英语：thread）是操作系统能够进行运算调度的最小单位。它被包含在进程之中，是进程中的实际运作单位。一条线程指的是进程中一个单一顺序的控制流，一个进程中可以并发多个线程，每条线程并行执行不同的任务。在Unix System V及SunOS中也被称为轻量进程（lightweight processes），但轻量进程更多指内核线程（kernel thread），而把用户线程（user thread）称为线程。—— 百度百科

用套娃的方式描述：一个操作系统中会运行多个程序，每个程序中可能包含多个进程，而进程中又可能包含多个线程。

至于为什么会诞生线程，其原因可以自行查询计算机组成原理相关内容，本文不做赘述，如果要简要梗概主要原因，说 “线程的出现，能提高 CPU 使用率” 是不为过的，它和计算机网络中的 分时复用 是类似的思想

线程的生命周期#

日常的软件交互中，软件并不是时时刻刻需要 CPU 的算力，在不需要算力的时候，软件完全可以把此时的 CPU 独占让给其他程序，减少 蹲坑不拉屎 的发生，提高 CPU 使用率。而这个让出 CPU 算力的机制便是通过线程的生命周期来实现的，不需要占用算力时进入 阻塞状态 等待需要时再被唤醒即可，Java 线程完整生命周期如图：

  • 新建状态: 使用 new 关键字和 Thread 类或其子类建立一个线程对象后，该线程对象就处于新建状态。它保持这个状态直到程序 start() 这个线程。
  • 就绪状态: 当线程对象调用了start()方法之后，该线程就进入就绪状态。就绪状态的线程处于就绪队列中，要等待JVM里线程调度器的调度。
  • 运行状态: 如果就绪状态的线程获取 CPU 资源，就可以执行 run()，此时线程便处于运行状态。处于运行状态的线程最为复杂，它可以变为阻塞状态、就绪状态和死亡状态。 阻塞状态: 如果一个线程执行了sleep（睡眠）、suspend（挂起）等方法，失去所占用资源之后，该线程就从运行状态进入阻塞状态。在睡眠时间已到或获得设备资源后可以重新进入就绪状态。可以分为三种：
    • 等待阻塞：运行状态中的线程执行 wait() 方法，使线程进入到等待阻塞状态。
    • 同步阻塞：线程在获取 synchronized 同步锁失败(因为同步锁被其他线程占用)。
    • 其他阻塞：通过调用线程的 sleep() 或 join() 发出了 I/O 请求时，线程就会进入到阻塞状态。当sleep() 状态超时，join() 等待线程终止或超时，或者 I/O 处理完毕，线程重新转入就绪状态。
  • 死亡状态: 一个运行状态的线程完成任务或者其他终止条件发生时，该线程就切换到终止状态。

线程的关闭#

线程的关闭大致分为两种，强制式的和非强制式的。我们不妨假定一个场景：公交司机“小张”此刻正驾驶公交车，运行在河道上。公交公司出于某种原因，现决定解雇“小张”。

  • 强制式: 公交公司要求”小张“瞬时、立刻、马上不得再碰公司的“资源”---公交车，于是“小张”无奈只好不再操控公交车，即便明知自己还没松油门、停车，危险性可想而知。
  • 非强制式: 公交公司给“小张”发了条通知“公司出于多方面考虑决定解雇你，你什么时候到公司的办事处，就什么时候把公司的“资源”---公交车还给公司吧”。

涉及的函数#

在 Thread 对象及其子类中：

函数含义
public final void stop()(慎用) 强制当前线程进入死亡生命周期，释放当前占用资源
public static boolean interrupted()返回对应线程的中断标志位是否为 true，重复调用则会清空标识(若某次调用返回 true ，那么第二次调用则会 清空 标识值，导致返回 false)
public boolean isInterrupted()单纯返回对应线程的中断标志位是否为 true
public void interrupt()主动将对应线程的中断标志位的值置为 true

Warning： 此处提及的除了 stop(), 其他方法基本可以理解为向线程传递了---你的上级想让你关闭了 这样的信息，至于线程自行关闭的逻辑，则需要开发者自行实现

关闭线程的具体方案#

  • 强制杀死线程： 调用线程对象的 stop(),或者关闭该线程所在的进程，均可能引发严重后果
  • 线程 run() 中代码执行完毕： 线程预定执行的任务完成后会自动进入线程的死亡生命周期，自行回收。复杂一点的情况，线程自己监听着“通知”，随即开始关闭线程。

  • 抛出异常： 在线程对象执行过程中抛出异常，也就达成条件 线程 run() 中代码执行完毕 进而就关闭进程了。 除此之外我要强调一下 Thread 对象的 interrupt()。在未发生死锁等复杂非预期情况下，如果线程对象被调用 interrupt() 时，该线程在调用 Object 类的 wait()、wait(long) 或 wait(long, int) 方法，或者该类的 join()、join(long)、join(long, int)、sleep(long) 或 sleep(long, int) 方法，那么该线程内部会抛出 InterruptedException 并自行关闭线程。

    也就是说 interrupt() 在某些特定情况下就不仅仅是 通知 了，而是 通知 的同时强制终止了目标线程。

线程的内存开销#

线程内存开销显然与该线程的业务逻辑有关，比如有没有递归，声明了多少局部变量…… 而在业务逻辑一定的情况下，人为也能影响到线程内存的开销 —— JVM 参数 -Xss___ 等价于 (-XX:ThreadStackSize=___) 样例： -Xss128k

Tips：JVM Stack(虚拟机栈) 的线程私有 栈帧 主要包括 局部变量表、操作栈、动态连接、方法返回地址

该参数会限制每个线程分配到的线程栈大小，所以对于内存一定的运行环境：

  • 该参数越大，能新建的线程越少，能使用的局部变量越多、栈深越深
  • 该参数越小，能新建的线程越多，能使用的局部变量越小、栈深越浅

程序设置的线程栈过小时，代码运行过程中会抛出 java.lang.StackOverflowError 异常
